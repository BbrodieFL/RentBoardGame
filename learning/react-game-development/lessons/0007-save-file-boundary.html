Save File Boundary

Your win for this lesson: explain why import/export uses the same save object as localStorage.

Do We Need This Lesson?

Yes, but only a small one. The shop mechanic was removed because it cluttered the game. The useful Milestone 5 idea that remains is the save-file boundary: turn gameSave into JSON text when exporting, then turn JSON text back into validated save data when importing.

Primary sources: MDN: JSON.stringify and MDN: JSON.parse .

Export: Object To Text File

const exportText = JSON.stringify(gameSave, null, 2);

Export does not invent a second save system. It takes the current gameSave object and serializes it into readable JSON text.

Import: Text File To Safe Save

const importedValue = JSON.parse(contents);
setGameSave(normalizeGameSave(importedValue));

Import treats the file as untrusted. The file might be old, broken, or hand-edited, so the app runs it through normalizeGameSave before using it.

Reset: Back To Defaults

setGameSave(createDefaultSave());

Reset uses the same default save shape as a brand-new browser. The confirmation prompt protects against accidental deletion.
