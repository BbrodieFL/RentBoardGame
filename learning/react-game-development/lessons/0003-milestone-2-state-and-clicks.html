React Game Development - Lesson 0003

Milestone 2: State and Clicks

This lesson is mostly about what we added in Milestone 2. The new concepts are the small React tools that make those additions possible.

What Changed From Milestone 1?

In Milestone 1, the screen was a poster: React rendered fixed data. In Milestone 2, the screen became a toy: clicking an activity changes what React remembers, and the screen updates from that memory.

The New Loop

Click "Code for 30 minutes"
  -> ActivityButton runs onClick
  -> App runs handleActivityLog(activity)
  -> App adds a new ActivityEntry to state
  -> React renders App again
  -> rent, XP, animation, and log now look different

Primary sources: React: Responding to Events and React: State - A Component's Memory.

The Important State

const [activityEntries, setActivityEntries] = useState<ActivityEntry[]>([]);
const [activeAnimation, setActiveAnimation] = useState<SpriteAnimationId>(characterDefaultAnimation);
const [floatingFeedback, setFloatingFeedback] = useState<FloatingFeedback | null>(null);

Read each line as: “React, please remember this value for me.” The first value is the current state. The second value is the setter function you call when the state should change.

Props Still Matter

<ActivityButton
  activity={activity}
  onLog={handleActivityLog}
/>

This is props again. App passes data with activity and passes a function with onLog. That lets the child button say “I was clicked” without owning the whole game state.

Stored vs Derived

We store activityEntries because the user creates those entries. But we do not store todayRentPoints; we calculate it from the entries: 

const todayRentPoints = activityEntries.reduce(
  (total, entry) => total + entry.rentPoints,
  0,
);

That means undo is simpler. Remove an entry, and the rent total naturally becomes smaller the next time React renders.
