React Game Development - Lesson 0004

How Browser Storage Is Used

Your win for this lesson: explain why activities survive a refresh even though React state normally resets.

Do We Need This Lesson?

Yes, a short one. Milestone 3 added one important concept: browser persistence. React state remembers things while the app is running. localStorage remembers strings for the same browser origin across page loads.

Primary source: MDN: Web Storage API .

The Save Bucket

The browser gives each origin its own storage bucket. This matters because the port is part of the origin: 

http://127.0.0.1:5173  // one localStorage bucket
http://127.0.0.1:5174  // a different localStorage bucket

The Project Save Key

export const gameSaveKey = 'oliver-tyrone-rpg-save';

Think of this as the drawer label inside the browser storage bucket. Our game always saves and loads using this same key.

Why We Use JSON

The Web Storage API stores keys and values as strings. Our game save is an object, so we serialize it before saving: 

storage.setItem(gameSaveKey, JSON.stringify(save));

Then we deserialize it when loading:

const rawSave = storage.getItem(gameSaveKey);
const parsedSave = JSON.parse(rawSave);

Sources: MDN: Using Web Storage , JSON.stringify , and JSON.parse .

The App Flow

const [activityEntries, setActivityEntries] =
  useState(() => loadGameSave().activityEntries);

This loads saved activities only when React creates the state for the first time. 

useEffect(() => {
  saveGameSave({
    schemaVersion: 1,
    activityEntries,
  });
}, [activityEntries]);

This saves whenever activityEntries changes. Log an activity: save. Undo an activity: save.

Practice In The Browser

Open DevTools, go to Application, then Local Storage. Look for the key oliver-tyrone-rpg-save. Log an activity and watch the value change.
